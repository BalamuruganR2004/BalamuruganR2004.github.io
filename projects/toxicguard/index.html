01 / THE PROBLEM

How can a reviewer assess harmful comments without losing control of the decision?

The solution

ToxicGuard combines text classification with a moderation interface. It returns six label scores and applies a risk policy so a reviewer can inspect and act on queued comments.

Implementation scope

The implementation connects saved TF-IDF and classifier artifacts to a FastAPI service, a browser interface, a risk policy, and SQLite persistence. The original trained artifacts are reused by the application.

03 / ENGINEERING DECISIONS

The reasoning behind the build.

01

Reuse trained artifacts

Load the existing vectorizer and classifier into the inference service. This connects model development to a usable application without retraining on each request.

02

Separate scores from policy

Classification returns label scores; a separate conservative policy maps risk to approval or review. Policy thresholds can evolve separately from the model.

03

Keep a review queue

SQLite stores moderation records so analysis supports a continuing workflow. Persistence introduces access-control and retention responsibilities.

05 / CHALLENGES ADDRESSED

Where the engineering matters.

Predictions need an operational next step

Constraint
Raw model scores do not tell a reviewer what to do.
Implementation
Keep scoring, risk policy, and moderation actions as distinct stages.
Takeaway
A model needs a workflow around it.

Inference must match training preparation

Constraint
A different text representation would invalidate saved model behaviour.
Implementation
Reuse the saved vectorizer and corresponding text-cleaning path.
Takeaway
Preprocessing is part of the model contract.

06 / BOUNDARIES

What comes next.

Current limitations

  • Label scores require validation and calibration for the intended community.
  • False positives and missed harmful content require human oversight.
  • Public moderation use needs authentication, authorisation, abuse testing, and retention controls.
  • The small API suite is a starting point, not comprehensive reliability evidence.

Next engineering steps

  1. Expand API tests for invalid input and moderation transitions.
  2. Evaluate thresholds and error patterns on representative comments.
  3. Add reviewer permissions and an audit trail for moderation actions.

THE TAKEAWAY

Serving a model is only one stage. The surrounding API, policy, stored state, and human review determine whether its output is useful.
